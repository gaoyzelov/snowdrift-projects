加一个坐标，得到一层能力。

Snowdrift 把微服务里总要重写一遍的那部分 —— 认证、缓存、消息、对象存储、调度、ORM、日志、请求上下文 —— 拆成 11 个功能模块、26 个可独立引入的构件。

26 个构件里有 20 个是带自动配置的 Spring Boot 模块，其余是纯基础库：引入坐标，能力生效；去掉坐标，它不参与启动。 不需要继承统一的父类，也不需要改启动类。基于 Java 17 与 Spring Boot 3.5，版本与 Spring Cloud 2025 对齐。

默认值

默认值不是随手填的

脚手架的一半价值在能力，另一半在默认值。下面每一条都能在代码里找到出处，也都留了开关 —— 但默认那一侧是保守的，因为「忘了配」比「配错了」更常见。

消息里的身份头，默认签名

snowdrift.mq.sign = true

消费端会用消息头里的 userId / tenantId 覆盖当前线程的身份上下文，所以这些头必须有完整性保护 —— 任何能往同一个 topic 发消息的一方都能伪造它们。 默认按 HMAC-SHA256 校验，sign-key 没配就直接启动失败，避免「生产者不签、消费者全收」这种最坏组合。

跨进程身份，默认不恢复

-Dsnowdrift.rpc.dubbo.trust-inbound-security-context = false

Dubbo 调用方可以往 attachment 里塞任意身份。默认不认；确实需要信任上游时，用 JVM 参数或同名环境变量 显式把这个开关打开，而不是让它默认成立。

租户对不上，直接失败

FieldAutoFillHandler

自动填充租户 ID 时，如果实体上的租户与上下文不一致，抛 BizException。 不照写、不静默放行 —— 跨租户写入是要立刻看见的错误。

接口文档，默认不对外

snowdrift.security.exclude-path-patterns

默认放行列表里只有 /favicon.ico 和 /error。 /v3/api-docs/**、/doc.html、 /swagger-ui.html 需要你自己加回去 —— 它们会把全部接口定义和参数结构暴露出去， 是否对外应该由你按环境决定，而不是由框架默认替你决定。

输入侧转义，默认关闭

snowdrift.xss.enabled / escape-parameters / escape-headers

snowdrift.xss.enabled 默认就是关的；即使打开，参数与 Header 的转义也各自默认关闭。 因为输入侧转义会改写数据本身：a&b 变成 a&amp;b、 Authorization 里的 & 被改写、 If-None-Match: "v1" 的引号被破坏。XSS 是输出上下文的问题，应该在渲染时按上下文编码。

审计日志，默认脱敏凭据

ApiLogAspect.DEFAULT_CREDENTIAL_SUFFIXES

password、token、secret 这类字段按后缀匹配，userPassword、csrfToken 同样命中， 不要求你在 @ApiLog 上逐个声明 mask —— 漏声明的代价是明文口令落进审计表。

引入

两步接入

先取源码安装到本地仓库，再用 BOM 统一版本仲裁。每个模块只依赖它自己需要的东西， 不会把没用到的后端 SDK 带进来。

1. 构建到本地仓库

当前尚未发布到 Maven 中央仓库，需要从源码安装。

Shell
git clone https://github.com/gaoyzelov/snowdrift-projects.git
cd snowdrift-projects
mvn clean install -DskipTests

2. 按需引入

引入哪个坐标，就得到哪一层能力。自动配置在引入后即生效，不需要写 @EnableXxx。

pom.xml — 版本由 BOM 仲裁
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>com.snowdrift</groupId>
      <artifactId>snowdrift-dependencies</artifactId>
      <version>1.0.0</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
pom.xml — 引入一个模块
<dependency>
  <groupId>com.snowdrift</groupId>
  <artifactId>snowdrift-orm-mp</artifactId>
</dependency>

响应契约

HTTP 状态码统一 200，成功与失败由响应体的 Result.code 表达，认证与鉴权异常也不例外。网关、前端与监控请按 body.code 判断，不要按 HTTP 状态码判断。
